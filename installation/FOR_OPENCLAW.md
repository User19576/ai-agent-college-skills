# OpenClaw installation guide

This route installs the four OpenClaw-specific copies in `openclaw-skills/` into one selected OpenClaw agent workspace and, only if separately chosen, proposes scoped `SOUL.md`, `USER.md`, and `MEMORY.md` additions. They use the native tools documented in [OPENCLAW_TOOLS.md](OPENCLAW_TOOLS.md), not Hermes tool names. Tool visibility depends on the selected agent's policy, provider, and runtime. PDF analysis can be partial; binary DOCX needs an available parser/converter. Do not claim skill discovery proves a coursework workflow works end to end. The course-specific rules reference is not another learner's policy.

OpenClaw's [skills guide](https://docs.openclaw.ai/tools/skills) and [CLI reference](https://docs.openclaw.ai/cli/skills) document workspace-scoped local skill installs. Its [workspace](https://docs.openclaw.ai/concepts/agent-workspace), [user model](https://docs.openclaw.ai/concepts/user-model), and [memory](https://docs.openclaw.ai/concepts/memory) guides explain the profile-file differences below. `openclaw skills install git:OWNER/REPO` is **not** the route for this repository: Git installs expect `SKILL.md` at the repository root, but this repository contains four separate skill directories.

## Inspect and propose — no writes yet

1. Fetch `README.md`, `DESIGN_PRINCIPLES.md`, this guide, `OPENCLAW_TOOLS.md`, each of the four `openclaw-skills/<name>/SKILL.md` files, and the OpenClaw academic skill's `references/` and `templates/` files from the supplied GitHub URL. Identify the revision inspected. Do not clone before approval. If any source file is missing, stop. Do not substitute a same-named folder from `skills/`: those are Hermes-specific. The examples below are OpenClaw-specific; `PROFILE_SUGGESTIONS.md` contains Hermes-specific paths and approval instructions, not this route's rules.
2. Identify the intended OpenClaw agent ID and its **actual configured workspace**, not a guessed `~/.openclaw/workspace`. Check existing same-named skills and local edits; resolve collisions before approval. OpenClaw can install into an agent workspace with `--agent <id>` or into the default workspace without it. Do not use `--global` unless separately requested. Read the selected workspace's `AGENTS.md`, `SOUL.md`, root `USER.md`, and root `MEMORY.md` if present; check whether this Gateway is single-user or shared, and how the selected agent resolves personal `USER.md`. Do not change another agent's workspace, Gateway config, or `AGENTS.md` under this plan.
3. Ask which optional `SOUL.md`, `USER.md`, and `MEMORY.md` examples below the user wants, with **skills-only** as an explicit choice. Use `ask_user` for choices if available, not to approve the plan; if it is unavailable, skipped, or times out, ask in chat and wait. Batch independent choices before the first preview. Ask for each exact identifier only after the user opts to save that field. If they confirm Network Administration as their course, strongly recommend the optional student-number entry, but do not require it or ask for the number before they opt in. The recommendation is not a verified brief requirement; use the number in coursework only where the current brief explicitly requires it. An install request or “add all” does not confirm preferences, identity, course policy, or consent to persist memory.
4. Preview the exact four local-source installs, destination agent/workspace, conflicts and backups. For each of `SOUL.md`, `USER.md`, and `MEMORY.md`, show a minimal completed diff or **no change** at its **actual** destination, including any existing overlapping text. Never preview or write unresolved placeholders or another learner's identifiers. If a shared Gateway uses personal instructions, show the chosen personal destination and existing shared defaults; do not substitute the shared root `USER.md`. If the user requests an external memory target, verify its supported write/read, ownership, backup, and mirroring first; do not guess or silently write both. Explain that shared workspace changes can affect other users, that a source checkout is not an agent workspace, and that installation alone does not prove document rendering. Identify every backup and replacement risk.
5. Stop after the combined preview. Ask for **`APPROVE OPENCLAW COLLEGE SKILLS INSTALL`** as the entire message for that exact file-by-file plan. Do not accept a generic “yes,” a choice selected in `ask_user`, or the initial prompt as approval. If a target, source, consent, or warning changes, show a revised plan and request fresh typed approval. No clone, skill install, or profile write before approval.

## Optional profile additions — propose only confirmed, non-duplicated text

OpenClaw's standard files are at the **selected agent workspace root**: `SOUL.md` for persona/stance, `USER.md` for user directives, and `MEMORY.md` for curated non-profile context. `memory/YYYY-MM-DD.md` is a separate daily-log directory; Hermes `memories/USER.md` and `memories/MEMORY.md` paths do not apply. OpenClaw recommends `AGENTS.md` for operating rules; do not duplicate existing rules in `SOUL.md` or edit `AGENTS.md` without a separate authorization. Workspace-root files can affect everyone using that agent. `MEMORY.md` is intended for the main private session, not shared/group contexts.

- **`SOUL.md`** (only if the user wants standing coursework behavior appropriate for this agent): candidate wording: “For coursework, read the current brief and project instructions first. Preserve learner authorship and distinguish reported instructor exceptions from verified brief text. Review from evidence; do not certify unchecked exports, screenshots, or submissions. Protect originals and edit only the authorized scope.” Keep it short and do not weaken the existing persona or rules. On a shared agent, propose **no change** unless the workspace owner explicitly approves its effect on all users.
- **`MEMORY.md`** (only if the user confirms this reusable workflow): candidate wording: “For assignment drafting, use a separate, clearly labelled non-submittable scaffold with evidence slots and learner-answer prompts, not model-written assessed prose. Record actual assistance in `AI-DISCLAIMER.md` for each assignment workspace. After learner-confirmed completion, preserve the submitted PDF, editable source, brief, and evidence; archive older drafts without deletion. Use the OpenClaw `academic-assignment-support` and `completed-assignment-cleanup` skills when available.” Keep this at the workspace root, not under `memory/`, and do not record it as universal course policy or a verified submission. On a shared agent, propose **no change** for an individual learner's workflow unless the owner approves a shared rule.
- **`USER.md`** (only confirmed facts/preferences): candidate identity clauses: “The learner identifies as [FULL_NAME] in coursework drafts for [COURSE]. Their student number is [STUDENT_NUMBER]; use it only where the current brief explicitly requires it. Never infer or store passwords from it.” Ask about `[FULL_NAME]`, `[COURSE]`, and `[STUDENT_NUMBER]` separately; omit unconfirmed clauses, not just the brackets. Optional preferences to confirm separately: concise replies; short screenshot-led practical reports; learner-written assessed prose; separate non-submittable scaffolds; review without edits until authorized; accurate AI-use records; preservation of originals and completed evidence; the Obsidian `COMPLETED - ` filename and bold **COMPLETED** heading convention only if they use that tracker and request it. Do not assume a `caveman` skill is installed in OpenClaw. Keep directives concise; OpenClaw gives `USER.md` a separate 4,000-character context budget and recommends dated active/superseded directives rather than contradictory entries.

On a **single-user Gateway**, propose the selected workspace's root `USER.md`. On a **multi-user Gateway** with distinct authenticated person profiles, workspace-root `USER.md` is shared; use the signed-in user's personal instructions for the selected agent via `personal_instructions` or **Settings → Profile → Personal instructions**, only if supported and available. The personal file lives under that workspace's `users/<canonical-profile-id>/USER.md`; never derive the ID from a display name, message, or email and never write another person's file. If there is no safe authenticated personal write/read path, propose **no change**, not a shared-root fallback. Check that the selected session actually loads the personal file; shared-owner logins, unauthenticated runs, and some harnesses do not provide per-person isolation. Personal files and workspace files are not secret stores.

## After typed approval only

1. Back up each affected installed skill directory and each approved workspace profile file without overwriting earlier backups. For personal instructions or an external provider, use a supported read/export or backup method; if no safe backup and read-back path exists, stop that edit rather than changing its destination. Preserve unrelated files and local skill edits. If a protected-file tool refuses a write, report the blocker; do not bypass it.
2. Obtain the reviewed repository revision in a temporary checkout. Compare its four OpenClaw skills and academic supporting files with the approved source before installing. From the checkout root run these commands for the selected agent (replace `ID` with its confirmed ID; omit `--agent ID` only for the confirmed default agent):

   ```sh
   openclaw skills install ./openclaw-skills/academic-assignment-support --agent ID
   openclaw skills install ./openclaw-skills/completed-assignment-cleanup --agent ID
   openclaw skills install ./openclaw-skills/assessment-evidence-audit --agent ID
   openclaw skills install ./openclaw-skills/assignment-export-verification --agent ID
   ```

   Stop on failure or an unexpected install-policy warning; do not use `--force` to bypass an unresolved conflict or policy decision. Report partial installs.
3. Apply **only** the approved minimal additions to the selected workspace's `SOUL.md`, `USER.md`, `MEMORY.md`, or explicitly approved personal/provider target. Preserve existing text and mark declined targets **no change**. Do not write the template's raw placeholders, shared-root user details on behalf of another person, the original learner's identity, course rules, or reported instructor exceptions as facts about the installer. A skills-only plan makes no profile changes.
4. Read back the exact target: run `openclaw skills list --agent ID` and `openclaw skills check --agent ID` (omit the agent selector only for the confirmed default). Inspect the four installed OpenClaw `SKILL.md` files and the academic `references/` and `templates/` copies in that agent's workspace. Read back each approved workspace file or personal/provider entry via its supported interface; confirm that **no change** targets remained untouched. A missing requirement or agent allowlist can hide an installed skill. Start a new session if its current skill snapshot is stale; personal instructions may appear on a later turn only in the eligible user's session. Confirm the needed OpenClaw tools are visible; test an actual document and image workflow before claiming it works. Report exact changes, backup locations, partial failures, and any missing parser, model, or page coverage. Do not infer that the current session reloaded changed profile files.
